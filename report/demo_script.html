Why this version is short. The full script ran 18–20 minutes in rehearsal. Talking is only half a demo — switching windows, scrolling to a cell and letting people read the screen costs as much again. So this is ~5 minutes of speech inside an 8-minute slot, and the slack is deliberate.
  • Say only what is written. Anything cut still exists in the report, and the Q&A table at the bottom covers what examiners actually ask.
  • Don't read numbers off the slide. The slide shows them; you say what they mean.
  • One screen move per segment. Every tab open before you start.
  • Finishing in 7:30 is better than being cut off at 10:00.
Never cut these four — they are the intent and scope of the project
  1. The problem and the user — a bank's first-line support desk must map each free-text message to one of 77 request types and reply safely (segment 1).
  2. What the system does — one message in, one validated decision out: intent, a customer-safe reply, an optional tool call, and a hand-over flag (segment 2).
  3. Why a generative model — a classifier gives only a label; one prompted pass gives label, reply and routing, and a new request type is a prompt edit, not a retrain (segment 2).
  4. The boundary we set — the model suggests, our code decides: nothing unvalidated reaches a customer and no card is blocked automatically (segments 5 and 6).

If you are running short, cut detail from E2, E3 or E6 — never from these four. They are what the brief's problem-definition and responsible-use requirements are graded on.

Likely questions, with the numbers ready

QuestionAnswerWho takes it
"Only 47.8%? Isn't that poor?"Yes — and we say so. It is a 77-way, fine-grained task with deliberately overlapping classes, no training, and a 1.5B model. The point of the project was the workflow and its controls, not a leaderboard number. The fix we identify is a LoRA adapter on the 10,003 training rows (§9).Satya
"Why is the baseline GPT-2 if it performs so badly?"Deliberately weak, to make the improvement visible and measurable. We also state its limit honestly: its 1,024-token context is shorter than our ~1,600-token few-shot prompt, so any GPT-2 few-shot number partly measures truncation, not capability (§13).Vishruth
"How do you know the few-shot examples didn't leak into evaluation?"Examples come only from the training split, and assert_no_overlap in the runner refuses to start if any example text is also an evaluation query. §7 states it; the preprocessing record logs the split sources.Vishruth
"Is the comparison statistically meaningful?"Paired on the same 385 messages, tested with exact McNemar: few-shot vs zero-shot p = 0.002, vs role/context p = 0.0002, vs constraint-based p = 0.002. The other three are indistinguishable (p 0.47–1.0), and we refuse to rank them.Satya
"Why two different GPUs?"A driver/CUDA mismatch: the newer torch build needed CUDA 13, which the server did not have. Both records are in Appendix F, within-experiment comparisons each come from one machine, and we rebuilt the evaluation sample on the second machine and confirmed it matched byte for byte.Vishruth
"What stops the model blocking someone's card wrongly?"block_card is never executed automatically — the router marks it as needing human confirmation, and our routing metric counts that withholding as correct, not as a miss. 14 of the 50 tool-triggering messages took that path.Kishore
"Your confidence value doesn't work. Why keep it?"Because reporting that it does not work is the honest result. It was effectively constant, so the 0.55 gate never fired; escalation is carried by the safety screen, failed validation, requires_human and the destructive-action rule instead. §11 and §13 both say so.Kishore
"Can every member explain the whole workflow?"Yes — and expect them to spot-check this. Each of you should be able to walk the pipeline diagram and name the four validation failure kinds: no_json_found, malformed_json, schema_violation, unknown_intent.anyone
"Where is the structured-output schema?"Pydantic model in schema.py, printed as Appendix C, with validated samples in Appendix E. Five model-owned fields; anything extra, missing or mistyped is rejected.Kishore
"What's the repair loop's actual benefit?"Validity 83.4% → 94.8% for few-shot. Broken down: 47 of 60 formatting failures rescued, 1 of 62 invented labels. We explain why — the retry does not re-state the label space — and name it as the next fix.Satya
