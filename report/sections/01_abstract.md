# 1. Abstract

Messages to a retail bank's support desk are short, informal and often ambiguous. A first-line agent must map each one to one of 77 request types, decide whether a system lookup is needed, and reply without inventing account facts. SafeBank Assist automates this triage with a pretrained, instruction-tuned causal language model, Qwen2.5-1.5B-Instruct, prompted to return one machine-readable JSON decision per message: the BANKING77 intent, a self-reported confidence, a customer-safe reply, an optional call to one of three simulated banking tools, and an escalation flag. Deterministic code surrounds the model: schema validation with a repair-retry loop, a check that every label exists in the dataset, a screen that withholds replies asking for credentials, a confidence gate, and a rule that a card is never blocked without human confirmation. We compare a GPT-2 baseline with four prompting strategies and six decoding configurations on a stratified 385-message evaluation sample, using six evaluation criteria. Few-shot prompting was the best strategy, at 47.8% accuracy and 0.450 macro-F1 across the 77 intents against 39.0–40.3% for the other three, with greedy decoding beating every sampled configuration; the repair loop raised valid structured output from 83.4% to 94.8%, rescuing formatting errors but almost never an invented label, and the safety screen withheld 15 replies, cutting replies flagged unsafe from 17.4% to 3.9%. Code, tests and the notebook are public (Appendix F).
